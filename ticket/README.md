# Ticket Input

Place one feature ticket per Markdown file in this directory.

Minimum structure:

```markdown
# TICKET-ID - Feature title

## Feature Description

Describe what is being built or changed.

## Acceptance Criteria

1. ...
2. ...
3. ...

## Additional Technical Information

Optional:
- API endpoint
- HTTP method
- request/response examples
- UI route
- database rules
- authorization
- business rules
- dependencies
```

The more precise the ticket is, the more precise the generated test suite will be.
